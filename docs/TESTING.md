# Testing Guardian

> **Status (2026-11-21):** 223 tests, all passing with `-race` against PostgreSQL 16 and Go 1.26, none skipped; also with
> `-shuffle=on -count=3`. Every requirement that is done has at least one test (generated table below). The whole
> suite takes about 30 seconds with `-race`.
> When something fails, read the message first: it may be a bug in the test, not in Guardian.

## Running

Unit tests need nothing:

```
go mod download
go test ./...        # database tests skip themselves
```

Database and end-to-end tests need a PostgreSQL database **dedicated to testing**. They truncate every table, so
they refuse to run unless the database name ends in `_test` and you opt in explicitly:

```
createdb guardian_test
export GUARDIAN_TEST_DB=1 DB_HOST=localhost DB_PORT=5432 DB_USER=postgres DB_PASSWORD=... DB_NAME=guardian_test
go test -race -count=1 ./...
```

Each test process takes a Postgres advisory lock, so packages can run in parallel without `-p 1`. A test's
reported time therefore includes waiting for that lock: measure one package alone before calling a test slow.
The end-to-end tests hash passwords with 1 MiB instead of 64 MiB (`auth.UseCheapHashesInTests`), since
hundreds of hashes under the race detector were most of their run; `internal/auth` keeps the real parameters.
CI: `.github/workflows/backend.yml` (at the repository root) runs everything against a Postgres service container and builds the image.

The management UI (`frontend/`) has no automated tests in the repository (the owner's choice, 2026-11-21):
`npm run check` type-checks it against the API types generated from `docs/openapi.yaml`, and each change is
checked in a real browser (Playwright, at desktop and phone width) before it is handed over. Its requirements
count as covered by the API and end-to-end tests of the same behaviour.

## Not covered (yet)

* Real browsers, TLS and the `Secure` / `__Host-` cookie path (tests run over plain HTTP). The sign-in pages'
  JavaScript (password show buttons, vertical centring) and their look are checked by hand.
* `TRUSTED_PROXY_HOPS` end to end (only the IP function is unit tested).
* Graceful SIGTERM shutdown, `/readyz` failing when the database is down, connection-pool limits.
* Kubernetes manifests and the NetworkPolicy: only in CI (the chart workflow's `install` job on kind), not in
  `go test`.
* Load and latency: use `guardian_http_request_duration_seconds{route="/token"}` and `guardian_tokens_issued_total` from a staging deployment.
* Delivery through a real mail server with TLS (tests use a fake SMTP server without TLS; Mailpit by hand).
* Real off-the-shelf apps: Grafana is checked by hand (`docs/LOCAL-GRAFANA.md`).

## Known fragile spots

* `TestRateLimitWindowsRollOver` and `TestE2ERPInitiatedLogout` sleep about two seconds (window rollover, ID token expiry).
* `TestE2ERPInitiatedLogout` shortens an app's token lifetime to 1 second to obtain an expired ID token.
* Metrics tests assume chi reports route patterns such as `/things/{id}` through `RoutePattern()`. The counters
  are global to the process, so metrics tests compare before and after.
* A test that changes the keyring or the signing keys must leave the database clean
  (`TestKeyringRotationReencryptsEverything` resets it): the next test process checks its keyring against what
  is stored before it starts.
* The route permission tests (`TestEveryRouteHasItsPermissionCheck`, `TestE2EEveryAPIRouteRefusesWhoMayNotUseIt`)
  compare middleware by function pointer: wrapping `httpx.Authenticate` or `httpx.AdminOnly` in another function
  hides it from them, and they fail.
